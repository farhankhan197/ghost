# Design System

Ghost's visual language is minimal, dark, and technical. It should feel like policy infrastructure for futuristic developers, not a mascot-led novelty tool.

## Direction

- ultra-dark backgrounds
- restrained violet/blue accents
- terminal-like rhythm
- sparse geometry
- precise alignment
- low ornamentation

Avoid horror tropes, cartoon ghosts, neon overload, and decorative clutter.

## Palette

| Token | Value | Use |
|---|---|---|
| `--bg-0` | `#02040A` | primary background |
| `--bg-1` | `#070B16` | elevated dark surfaces |
| `--bg-2` | `#0C1024` | subtle section separation |
| `--accent-violet` | `#8B5CF6` | highlights and borders |
| `--accent-purple` | `#A855F7` | primary glow |
| `--accent-blue` | `#60A5FA` | secondary accent |
| `--text-primary` | `#F5F7FF` | main text |
| `--text-secondary` | `#94A3B8` | secondary text |
| `--text-muted` | `#64748B` | quiet labels |

## Typography

Use a geometric sans family such as Space Grotesk, Sora, General Sans, Neue Montreal, or Inter Tight.

CLI output should prioritize:

- short labels
- aligned columns
- wrapped long paths/models
- no mascot text
- "Ghost" capitalization

## Interface Rules

- Prefer dense, readable operational screens over marketing layouts.
- Show only information useful to the current command.
- Use stable widths and wrapping for paths, agents, models, and percentages.
- Do not let decorative elements compete with audit results.
- Keep cards and borders subtle.

## Product Tone

Ghost should read as:

- precise
- enforceable
- quiet
- security-minded
- transparent

It should not read as:

- playful mascot software
- spooky horror branding
- vague AI marketing
